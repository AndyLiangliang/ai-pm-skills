# 模式 A：竞争与进入（场景 9–12 摘要）

在 21 格和用户校验之后读取。用于拆已有产品，或可行性通过后问「怎么打进去」。

## 先问两个问题

1. 主导产品满足的**核心需求点**是什么？（Who → 需求）
2. 用户换到新方案的**替代成本**高还是低？（用户视角 How much）

替代成本低 = 容易抢。替代成本高 = 必须选对打法，不能只靠功能更多。

## 替代成本五要素

评估切换难度时逐项打分（高/中/低），不要只说「习惯了」：

| 要素 | 含义 |
|------|------|
| 习惯 | 操作记忆、流程嵌入日常 |
| 数据 | 历史数据、配置、知识库迁不走 |
| 付费 | 合约、预付、年费锁定 |
| 功能 | 关键能力尚无替代 |
| 网络协同 | 同事都在用、生态插件、上下游接口 |

ToB / 企业系统通常「数据 + 付费 + 网络协同」同时高，不要按工具 App 的低替代成本来写。

## 频率 × 替代成本四象限

| | 低替代成本 | 高替代成本 |
|---|---|---|
| **高频** | 流量拦截（同类渠道抢注意力） | 弯道超车或利基（微信、浏览器这一类最难） |
| **低频** | 流量拦截（工具类，最容易） | 资源效率 / 等待时机（企业核心系统） |

落到象限后只给**该象限的打法**，不要四个都写一遍。

## 打法速查

**流量拦截（低替代）**：在对方已经跑通的渠道上复刻链路，比的是触达和转化，不是重新发明品类。

**资源效率（低频 × 高替代）**：结硬寨打呆仗。找到第一性发力点（成本、交期、交付确定性），用效率而不是广告硬撞。适合你熟悉的供应链、渠道、交付型生意。

**弯道超车（高频 × 高替代）**：需要迁移成本被重置。常见两种：

- 平台迁移：用户界面变了（PC→移动，独立 App→钉内/企微），习惯清零
- 技术代际差：新功能价值明显大于替代成本，旧玩家受「创新者窘境」拖累

没有界面迁移或代际差，就不要把「弯道超车」当套话。

**利基**：主流产品为了服务最大公约数，会故意忽略某些客群（主流悖论）。用 AB 分类把「主流不服务、但你能服务好」的细分写具体（角色、预算、渠道、合规），不要写成「做差异化」。

## 壁垒类型 → 竞争方式

| 对方壁垒 | 硬撞通常无效 | 更可能有效 |
|----------|--------------|------------|
| 网络效应 | 功能对标 | 新场景、新平台、利基圈层 |
| 数据飞轮 | 同质内容 | 独特数据源或工作流嵌入 |
| 切换成本 | 价格战 | 降低迁移成本、兼容、代运营 |
| 品牌/信任 | 广告对砸 | 背书、样板客户、原厂/渠道信任 |
| 成本优势 | 同样玩法 | 另一套成本结构（如小单快反） |

## 模式 A 报告里必须出现的三行

1. 象限定位（频率 × 替代成本）
2. 五要素里最高的 1–2 项
3. 因此选择的**一种**打法，以及明确不选的打法（避免既要流量拦截又要弯道超车）
