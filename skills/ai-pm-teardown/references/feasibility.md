# 模式 B：可行性链（场景 1–3）

只在「值不值得做」时读取。顺序固定：先判断需求与价值，再算一单，再算项目。

## 场景 1：首尾两端

创意是「可以怎么做」。管理是「要不要做」。这里只做管理。

### Kano 初筛

| 属性 | 处理 |
|------|------|
| 反向 / 无差异 | 直接淘汰，不进 21 格 |
| 必备 | 必须做，但不是卖点 |
| 期望 | 竞争主战场 |
| 魅力 | 差异化候选 |

从需求反推画像，只抓与需求相关的特征，不做完整用户研究。

### 粗估

```
粗估价值 = 目标用户规模 × 单个用户价值
```

先不深究界面、技术、竞品。目的是快速否决，不是精确 TAM。

### 首尾两端

```
首端：需求是不是真的？
中间：方案 / 竞争 / 定价 / 技术 —— 先跳过
尾端：解决它有没有足够价值？
```

两端成立，才进入场景 2。中间项不是本步否决理由。

### 陷阱

发现痛点后立刻设计功能、Agent、Prompt，等于用思考时间给方案制造沉没成本。正确顺序是：痛点 → 价值判断 → 值得做才想方案。

## 场景 2：MVP 测算（UE 正不正）

前提：场景 1 已过。下面每步的输出是下一步的输入。

```
痛痒爽 → 商业模式
  → 定价（客单价锚）
  → 用户隐性成本（阻力）
  → 转化率
  → 触达用户价值 = 客单价 × 转化率
  → vs 每触达一次的服务成本
  → UE 正 / 不正
```

### 痛痒爽 → 怎么赚钱

- 痛 → 直接收费
- 痒 → 必须溢价，否则小众收不回成本
- 爽 → 走规模

判错这一步，后面的账全废。

### 定价

找用户心里已有的人工/旧方案价格当锚。AI 常见击穿心智区间是人工价的 **5%–10%**（经验区间，不是定律）。ToB 硬件/方案类用「原有采购预算、人月、渠道加点」当锚，不要硬套 C 端 39 元逻辑。

保守测算用**最低客单价**，防止乐观。

客单价心理阈值：大约 **500 元** 以上，自助转化会显著变难，更多依赖销售说服（见 growth 里的高客单链）。未读 growth 时，高客单至少把转化率往下调，并提高交易成本。

### 隐性成本 → 转化率

社会成本 / 使用成本 / 替代成本高，则不能用行业基准转化率，必须打折。

低客单、阻力小、痛点刚需时，可用参照区间（仅作底稿，必须标明假设）：

| 等级 | 付费转化率 |
|------|------------|
| 底线 | 3%–5% |
| 优秀 | 8%–15% |

ToB 1v1 销售不要套信息流转化率。改用：线索→商机→成交 的漏斗，或用户给的历史成交率。

### 口径必须一致

```
触达用户价值 = 付费用户价值 × 付费转化率
```

价值端和成本端都按「一次触达」比。不要拿 39 元客单去比 0.63 元每次 API，却假装转化率是 100%。

```
UE 毛利（每单或每触达，口径写清）= 对应收入 − 可变服务成本
```

UE 打不正：卖得越多亏越多，项目不可行。不要靠「做品牌」「以后再收费」跳过这一格，除非用户明确接受补贴并写出谁出钱。

案例锚（仅帮助理解数量级，不要照抄）：AI 改简历客单 39 元、服务成本 0.63 元/触达、转化 4%–11.5% → 触达价值 1.56–4.49 元，UE 为正。

## 场景 3：项目整体投入

UE 正 ≠ 项目可行。还要覆盖固定成本与前置投入。

```
项目成本 = 一次性开发（前置）+ 每月维护（固定）
月度盈亏平衡单量 = 每月固定成本 / 每单毛利
前置回收单量 = 前置投入 / 每单毛利
目标回收期内月单量 = 盈亏平衡单量 + 前置回收单量 / 目标月数
```

然后问：**可触达流量 × 转化率 是否大于目标月单量？** 没有 2 倍左右冗余，把「流量假设」标成高风险 🟡。

AI 产品的服务成本默认含 token，不要当成软件复制的零边际成本。

## 模式 B 的出口

| 结果 | 下一步 |
|------|--------|
| 场景 1 否决 | 停止。不要开工 |
| UE 不正 | 停止，或只讨论改定价/成本结构，不进入 scaffold |
| UE 正但流量撑不住 | 条件做：先证明渠道，或缩小范围 |
| 回本与流量都过 | 建议 `/ai-pm-idea-clarify`，可把本报告当作输入 |
