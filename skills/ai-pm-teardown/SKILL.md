# AI PM 产品/项目拆解

把一个产品或项目拆成可辩护的商业判断。脊骨是 **5W2H Max**（企业视角 7×3=21 格 + 用户视角校验），不是教科书七问，也不是开工包。

拆完如果结论是「值得做」，再建议进入 `/ai-pm-idea-clarify` → 开工链。不要在本 skill 里写 PRD 或技术方案。

## 先选模式

根据用户意图选一个默认模式。选错会把拆竞品做成头脑风暴，或把可行性做成百科。

| 模式 | 何时用 | 主路径 |
|------|--------|--------|
| **A 拆已有产品** | 竞品、同事的产品、自己已上线的产品 | 21 格逆向填表 → 用户校验 → 竞争象限 |
| **B 拆待做项目** | 「这个想法值不值得做」「这个项目能不能上」 | 场景 1–3：首尾两端 → UE → 回本与流量 |
| **C 已上线怎么提升** | 转化差、流量不够、客群窄、LTV 低 | 先 A 或 B 的结论，再读 [growth.md](references/growth.md) |

用户没说清时，用一句话确认模式，不要同时跑 A+B+C。

## 判断优先

用户在自己熟悉的领域（销售、行业客户、自己做过的产品）时：

1. 先让用户对 **Who / Why / How much** 给出预判（用户是谁、为什么付钱、一单大概多少钱）。
2. 再填 21 格、挑战口径和证据。
3. 最终「做 / 不做 / 条件做」由用户拍板。

用户在陌生领域时，先用框架填表，再请用户校准 3 个最关键的格子。

最多追问 5 个问题。优先问：付费的人是谁、现在怎么凑合、客单价锚点、一单可变成本、用户换产品有多难。

## 执行流程

### 0. 读输入

收集：产品名/项目名、公开信息、用户已知数据、可选的知识库笔记。信息不够就追问，不要假装 21 格都填得上。

### 1. 填 21 格

读取 [matrix-21.md](references/matrix-21.md)。每格标记：

- 🟢 **可观测**：公开事实、用户给出的数、可核验截图/价格页
- 🟡 **可推断**：有锚点的估算，必须写假设和口径
- 🔴 **不可知**：没有证据。禁止写成「待验证」后当结论用

只有 🟢 和 🟡 能进结论。🔴 要么三角化成 🟡，要么明确「本格不下结论」。

### 2. 用户视角校验

用用户视角检查企业视角有没有自嗨：

- Who：画像是否具体到岗位/场景，而不是「企业」或「用户」
- Why：痛 / 痒 / 爽 三选一，并写出对应商业化逻辑（痛→收费，痒→溢价，爽→走量）
- How much：直接成本之外，社会成本 / 使用成本 / 替代成本会不会挡购买
- When & Where：需求场景 ≠ 消费场景 ≠ 使用场景

### 3. 按模式走决策链

**模式 A**：读 [compete.md](references/compete.md)。用频率 × 替代成本落到四象限，给出进攻/防守含义。不要默认「做差异化」。

**模式 B**：读 [feasibility.md](references/feasibility.md)。严格按顺序：

1. Kano 初筛 + 首尾两端（先不要设计方案）
2. 痛痒爽 → 定价锚 → 隐性成本 → 转化率 → 触达用户价值 vs 服务成本 → **UE 正不正**
3. UE 正之后才算月度盈亏平衡、前置成本回收、流量是否撑得住

中间跳到功能清单或技术架构，就是掉进「顺着痛点想方案」的陷阱。

**模式 C**：主报告先给出 A 或 B 的一句话诊断，再读 [growth.md](references/growth.md) 只跑用户点名的那一个杠杆（转化 / 流量 / 客群 / 付费深度）。

### 4. 输出报告

按下面模板输出。缺数就写假设，不要编精确到小数点后两位的假账。ToB / 复杂交易场景要显式写 **交易成本** 和 **信任建立成本**（销售轮次、演示、合同），不要按互联网自助下单默认转化率。

若用户要求落盘，默认写到当前项目 `docs/TEARDOWN-[产品或项目名].md`；已有同名文件则先问是否覆盖。

## 约束

- 一次只拆一个产品或项目。
- 不把 15 个经典思维模型或知识地图整包铺进报告。需要竞品步骤壳时，用「范围→信息收集→对比维度→差异→策略→动作」，格子仍用 21 格填。
- 不把教科书 5W2H 当成 Prompt 模板；本 skill 的 5W2H 只用于商业拆解。
- Token / GPU / 履约人工计入 **服务成本**，销售提成 / 渠道分成 / 信任建立计入 **交易成本**，研发与摊销计入 **项目成本**。三者不要混在一个「成本」里。
- 结论必须带观测等级。没有 🟢🟡 支撑的「建议立刻做」视为失败输出。
