# AI PM 项目骨架生成

## 任务

基于前序输出，生成 AI 项目启动所需的核心文档，让项目从"想法"变成"可执行的工程包"。

## 输入

- `ai-pm-idea-clarify` 输出
- `ai-pm-solution-design` 输出
- `ai-pm-prompt-consultant` 输出

## 输出文件

默认在当前项目根目录生成以下文件：

```text
project-root/
├── docs/
│   ├── PRD.md
│   ├── TECH_DESIGN.md
│   └── EVALUATION_PLAN.md
├── AGENTS.md
└── _PROGRESS.md
```

## 生成流程

1. 检查当前目录是否已有同名文件，避免覆盖。
2. 如果用户已有部分文档，只补充缺失部分，并询问是否更新已有内容。
3. 按模板生成 5 份文档。
4. 生成 `_PROGRESS.md`，记录当前阶段和下一步计划。

## 文档模板

### PRD.md 结构

```markdown

## 1. 产品概述
- 一句话说明：
- 目标用户：
- 核心问题：

## 2. MVP 范围
- 做：
- 不做：

## 3. AI 能力设计
- 模型选型：
- RAG/Agent 架构：
- MCP/Skills 设计：
- 评估指标：

## 4. 用户流程
- 触发 → 步骤 → 成功/失败

## 5. 页面/功能清单
- 页面 1：
- 页面 2：

## 6. 非功能需求
- 性能：
- 安全：
- 可观测性：

## 7. 验收标准
- Tier 0（必须完成）：
- Tier 1（验证后完成）：
```

## 执行规则

- 所有文档正文使用中文，技术术语、代码变量、API 路径、文件路径保留英文。
- 如果当前目录不存在，询问用户是否创建。
- 如果文件已存在，询问是否覆盖、合并或跳过。
- 生成的文档应该是"初稿"级别，不要追求完美，优先完成骨架。
