# RAG / Agent 架构模式参考

## 产品类型判断

### RAG 型产品

特征：
- 核心是从知识库中检索并生成答案
- 用户输入是问题，输出是答案
- 需要引用来源

典型场景：
- AI 客服
- 企业知识库问答
- 文档助手
- 学习助手

关键设计点：
- Chunk 策略
- 检索策略（向量检索、关键词检索、混合检索）
- 重排序
- 引用溯源
- 幻觉控制

### Agent 型产品

特征：
- 核心是多步任务执行
- 需要调用工具
- 有状态、有记忆

典型场景：
- 旅行规划 Agent
- 销售助手
- 数据分析师
- 个人助理

关键设计点：
- Agent 范式选择（ReAct / Plan-and-Solve / Reflection）
- 工具定义（Function-Calling / MCP / Skills）
- 记忆设计（短期记忆、长期记忆）
- 错误处理与重试
- 人在回路

### 嵌入式 AI 型产品

特征：
- 在现有产品中增加 AI 能力
- 不改变主产品流程，只是增强某个环节

典型场景：
- 微信读书 AI 问书
- Notion AI
- 飞书智能伙伴

关键设计点：
- 场景嵌入位置
- 触发时机
- 用户权限和数据边界
- 回退机制

### 多 Agent 型产品

特征：
- 复杂流程需要多个 Agent 协同
- 每个 Agent 负责一个子任务
- 需要编排层

典型场景：
- 营销自动化
- 复杂客服系统
- 内容生产流水线

关键设计点：
- Agent 分工
- 编排方式（串行、并行、动态循环）
- 通信协议
- 冲突解决
- 全局状态管理

## Agent 范式选择

| 范式 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| ReAct | 工具调用、环境交互 | 边想边做，灵活 | 步骤可能过多，成本高 |
| Plan-and-Solve | 复杂任务、明确目标 | 先规划后执行，可控 | 对变化适应性差 |
| Reflection | 需要自我改进的任务 | 能自我修正 | 增加延迟和成本 |

## 工具层选择

| 方式 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| Function-Calling | 自有 API 调用 | 直接、可控 | 需要维护工具定义 |
| MCP | 标准化工具接入 | 生态丰富、可复用 | 需要 MCP server |
| Skills | 项目内复用的工具封装 | 轻量、项目内一致 | 自定义程度高 |
