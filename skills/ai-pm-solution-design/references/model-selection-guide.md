# 模型选型指南 — 三看一测

## 三看一测框架

### 一看：看榜单

参考公开评测：
- LMSYS Chatbot Arena
- OpenCompass
- C-Eval / CMMLU（中文评测）
- MMLU、HumanEval、GSM8K

**注意**：榜单是通用能力，不直接等于业务场景能力。

### 二看：看数据

关注模型在目标场景下的表现数据：
- 长文本理解能力
- JSON 结构化输出稳定性
- 特定领域（法律、医疗、代码）表现
- 多语言/中文表现
- 推理速度、价格

### 三看：看客户

参考同行业或同场景的实际使用反馈：
- 相似产品用的什么模型
- 社区讨论中的实际体验
- 成本真实案例

### 一测：实测

用 3–5 个真实样本做快速测试：
- 准备用户场景中的真实输入
- 测试模型的输出质量、稳定性、响应速度
- 记录失败案例和边界情况

## 常见场景选型建议

| 场景 | 推荐模型类型 | 原因 |
|---|---|---|
| 通用对话/客服 | GPT-4o / Claude 3.5 Sonnet / DeepSeek-V3 | 综合能力强，中文支持好 |
| 复杂推理/规划 | Claude 3.5 Sonnet / o1 / DeepSeek-R1 | 推理能力强 |
| 代码生成 | Claude 3.5 Sonnet / GPT-4o / Cursor 内置 | 代码能力强 |
| 成本敏感/高并发 | 开源模型 / 国产模型（DeepSeek、Qwen、GLM） | 成本低，可控 |
| 私有化/敏感数据 | 本地部署 Llama / Qwen / GLM | 数据不出域 |

## 注意事项

- 不要只选最先进的模型，要选最适合场景和预算的模型。
- 考虑混合模型策略：简单任务用便宜模型，复杂任务用强模型。
- 记录实测样本，作为后续迭代的基准。
