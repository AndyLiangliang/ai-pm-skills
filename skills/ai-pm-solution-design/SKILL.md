# AI PM 方案设计

## 任务

基于澄清后的产品定位，设计 AI 产品的技术方案，并给出可验证的评估指标。

## 输入

- `ai-pm-idea-clarify` 的输出
- 可选：用户的技术偏好（如 Python/FastAPI、Next.js、Coze、Dify）
- 可选：用户指定的模型偏好或预算约束

## 执行流程

1. **判断产品类型**
   根据需求特征，判断属于以下哪种类型：
   - **RAG 型**：核心是从知识库中检索并生成答案
   - **Agent 型**：核心是多步任务执行、工具调用
   - **嵌入式 AI 型**：在现有产品中增加 AI 能力（如 AI 问书、AI 客服）
   - **多 Agent 型**：复杂流程需要多个 Agent 协同
   - **生成式内容型**：核心是大段内容生成（文案、代码、设计稿）

2. **模型选型**
   使用"三看一测"框架：
   - 看榜单：公开评测（如 LMSYS Chatbot Arena）
   - 看数据：模型在目标场景下的表现数据
   - 看客户：同行业或同场景的实际使用反馈
   - 实测：用 3–5 个真实样本做快速测试

3. **架构设计**
   - RAG 方案：Chunk 策略、检索策略、引用溯源、重排序
   - Agent 方案：ReAct / Plan-and-Solve / Reflection 选择、工具定义、记忆设计
   - 多 Agent 方案：编排方式（串行/并行/动态循环）、Agent 分工、通信协议
   - 工具层：Function-Calling / MCP / Skills 选择

4. **评估设计**
   使用 AI 产品评估三层体系：
   - 在线监控：用户满意度、任务完成率、错误率
   - 离线评估：准确率、召回率、F1、人工评分
   - 风险分级：幻觉、偏见、隐私、安全红线

5. **成本估算**
   - Token 成本估算
   - 基础设施成本（云服务、数据库、向量库）
   - 人力成本（是否需要标注、评测、运维）

## 约束

- 不替用户做最终技术决策，而是给出可对比的方案和推荐。
- 每个推荐都要说明理由和验证方式。
- 如果用户没有技术背景，避免过度深入实现细节。
